# AIS Governance and Data Contract (AIS-4)

## Status

AIS is read-only analytics and reporting in the current release. Contract
version `AIS-4.0` provides scope-aware aggregation, immutable snapshots,
analytical dashboard views, status distributions, attention indicators,
reproducible snapshot trends, immutable reports, review-only alerts, protected
CSV/PDF exports, and deployment hardening. Operational write actions and
professional decisions remain disabled.

## Ownership boundary

Core, IAP, AEMS, CMS, and ARMIS remain the authoritative owners of their
records. AIS may consume approved, scope-filtered records in read-only mode.
AIS must never overwrite source records, validate findings, finalize reports,
close recommendations, alter IAP plans, or change ARMIS provider authority.

## Source contract

| Source | Records AIS may consume | Authority |
| --- | --- | --- |
| Core | Users, offices, areas, focuses, classifications | Core |
| IAP | Approved strategic/annual plans, risk and prioritization results | IAP |
| AEMS | Engagement progress, fieldwork, evidence, findings, reports, closure | AEMS |
| CMS | Finalized recommendations, action plans, monitoring and validation outcomes | CMS |
| ARMIS | Availability, competencies, workload, assignments, person-day reconciliation | ARMIS |

All source queries reapply office, engagement, role, and confidentiality scope.
AIS does not create a second copy of source ownership or bypass Core Document
Version protections.

## AIS-1 data foundation

The AIS-owned `ais_aggregation_snapshots` table stores the generated scope
snapshot, source versions, query contract version, aggregated metrics, actor,
timestamp, and SHA-256 checksum. Snapshot history is actor-scoped so a user
cannot discover another user's restricted aggregation. Source rows remain the
system of record.

Every snapshot is immutable: model updates and deletes are rejected. The
generation action records both Activity Log and Audit Trail events with the
actor, checksum, source query version, and snapshot code.

## Professional controls

- AIS-1 is read-only and never mutates Core, IAP, AEMS, CMS, or ARMIS.
- AIS-2 analytical views are derived from scope-filtered metrics and immutable
  snapshots; they do not become a second workflow or decision authority.
- AIS-3/4 reports and exports are generated by the backend from an immutable
  result snapshot. CSV formula injection is mitigated, checksums are preserved,
  and downloads require `ais.export` through authenticated endpoints.
- AIS-3/4 alerts are review indicators only. They never issue notices, close
  cases, validate findings, or modify a source workflow.
- Automated analytics cannot make professional audit decisions.
- Published intelligence requires human review and an attributable actor.
- Confidential and restricted records remain protected at discovery and download.
- AIS exports, when separately approved, must be authenticated, scope-aware,
  reproducible, and audit logged.
- AIS-4 applies named per-actor/IP rate limits to reads, snapshot/report
  generation, and exports. Limits are configurable through
  `AIS_READ_RATE_LIMIT`, `AIS_GENERATE_RATE_LIMIT`, and
  `AIS_EXPORT_RATE_LIMIT` (defaults 120/12/20 per minute).
- Read responses use private, short-lived cache headers and protected file
  downloads use `private, no-store`, `nosniff`, and `no-referrer` headers.
- AIS view, contract, report-catalog, dashboard, alert, and run-access events
  are recorded in both Activity Log and Audit Trail. Diagnostics do not expose
  SQL details, filesystem paths, or public document URLs.
- AIS hardening is defense in depth; source scope, confidentiality, immutable
  models, and the separate `ais.export` permission are rechecked on every
  protected operation.

## Permission and API contract

- `ais.view` permits access to the governance contract and read-only foundation.
- `ais.export` permits protected report export and download only; it does not
  enable source-module writes or professional decisions.
- `GET /api/ais/contract` returns the authenticated actor's contract version,
  scope, source modules, controls, and planned phases.
- `GET /api/ais/hardening` returns authenticated deployment-control metadata,
  rate limits, cache policy, and enforced security checks without secrets.
- `GET /api/ais/aggregations` returns live scope-aware source metrics and the
  actor's latest snapshot metadata.
- `GET /api/ais/dashboard` returns the AIS-2 analytical dashboard contract:
  headline indicators, status distributions, human-review attention items,
  and actor-owned snapshot trends.
- `GET /api/ais/reports` returns the AIS-4 report catalog and export controls.
- `GET /api/ais/reports/runs` and `GET /api/ais/reports/runs/{run}` return
  immutable reports generated by the authenticated actor.
- `POST /api/ais/reports/{report}/generate` creates an immutable report run.
- `GET /api/ais/alerts` returns review-only analytical indicators.
- `POST /api/ais/reports/runs/{run}/exports` creates a protected CSV/PDF export
  for users with `ais.export`.
- `GET /api/ais/report-exports/{export}/download` is the authenticated private
  download endpoint.
- `GET /api/ais/aggregations/snapshots` returns only snapshots generated by the
  authenticated actor.
- `POST /api/ais/aggregations/snapshots` creates one immutable snapshot and
  records Activity Log and Audit Trail events. It does not copy source rows.
- `/audit-intelligence-system` is a read-only governance and analytical
  dashboard. It does not issue findings, close recommendations, or mutate
  source records.

## Planned phases

1. **AIS-1** - Read-only data foundation and aggregation services (implemented).
2. **AIS-2** - Intelligence dashboard and analytical views (implemented).
3. **AIS-3** - Reports, trends, alerts, and protected exports (implemented).
4. **AIS-4** - Security, performance, audit, and deployment hardening (implemented).

Each phase requires focused tests and a verification checkpoint before the next
phase begins.
